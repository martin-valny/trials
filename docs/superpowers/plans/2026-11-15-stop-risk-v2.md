# Stop-risk v2 (AACT point-in-time) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Train the stop-risk model on how trials looked while running (AACT snapshots), compare it fairly with v1 on the same held-out running trials, and ship it only if it clears the bar fixed in the spec.

**Architecture:** A ported HTTP-range reader pulls single tables from AACT monthly archives into a compact, git-ignored panel. An adapter turns each snapshot into the same `Tables` + `RiskFields` the daily run builds from the CT.gov API, so v1 features reuse `risk/features.build` unchanged and v2 adds point-in-time features beside it. A hand-run trainer builds cutoff-based train/test rows, fits every model in spec §7.2, applies §7.3, and writes the usual `config/risk/` artefacts; the daily run picks the feature builder from the card.

**Tech Stack:** Python 3.12, polars, httpx, scikit-learn 1.9 (pinned), joblib, pytest; web: React 19 + TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-11-15-stop-risk-v2-design.md` (read it first; v1 spec `2026-11-09-stop-risk-model-design.md` and `config/risk/README.md` for context).

## Global Constraints

- Cutoff C = the 2021-12-01 snapshot; outcome snapshot = 2026-01; label TERMINATED → 1, COMPLETED → 0; WITHDRAWN, SUSPENDED, UNKNOWN, still running, missing → excluded and counted.
- Scope at a snapshot: interventional; phase 1, 1/2, 2, 2/3, 3; ≥ 1 DRUG or BIOLOGICAL intervention; status in `risk.scope.RUNNING`; not finished-in-all-but-status (results posted by the snapshot date, or ACTIVE_NOT_RECRUITING with ACTUAL primary completion date before it).
- Shipping bar (frozen): boosted over v2-baseline needs AUC ≥ +0.02 and Brier no worse; v2 replaces v1 only if AUC ≥ v1-recipe + 0.02 and Brier ≤ v1-recipe on the §7.1 test set, and parity passes (≤ 1% mismatch per shippable feature; sponsor features exempt). Main fit of each ensemble.
- Never print, copy or commit the AACT credentials; read them at runtime from a path argument (default `~/Desktop/event-signal-backtest/data/raw/aact/.credentials`). Never import from the event-signal-backtest repo; reading its data files is allowed.
- Raw AACT data only under `pipeline/.cache/aact/` (git-ignored); raw extracts deleted after folding into the panel. Committed: model, card, held-out table (no NCT ids, no text), sponsor aggregate, factor labels, README.
- No new runtime dependency (use `httpx`, not `requests`). Daily run: no new network calls, no training.
- Wording: "estimated chance of stopping early"; factor labels describe the trial's own value, never "delayed"/"stale"/"overdue".
- Credit ClinicalTrials.gov and AACT/CTTI, the snapshot range and the processing date wherever v2 numbers appear (README, card, Methods).
- Do not read test-set metrics before Task 8's script prints them in one go; no tuning after that print.
- Time box ~4 days of model work; past it, stop and ask Martin.
- Never push; Martin pushes from a git bundle.

## Review Focus

1. An AACT enum value never seen in tests (e.g. a new status spelling, "N/A" phase, lower-case variants across years) — must fail loudly in the adapter, not silently map to null. Test in Task 3.
2. A trial that appears, disappears and reappears across snapshots (record missing from one archive) — training rows use only snapshots where it is present; label uses 2026-01 only; missing in 2026-01 → excluded and counted. Test in Task 6.
3. Dates with month precision only ("2019-05") and missing start dates — age / duration / overdue become null, never a crash or a 1970 epoch. Test in Task 4.
4. Archive download interrupted mid-table — the panel builder resumes without duplicating that snapshot's rows. Test in Task 2.
5. A live record whose type says ACTUAL enrollment while still running — `enrollment_anticipated` is 0 and enrollment is still used, same in AACT and live. Test in Task 4 and in parity (Task 9).
